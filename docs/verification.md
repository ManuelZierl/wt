# Verification

The acceptance suite exercises the CLI through the built `wt` binary and validates real submissions, disk manifests, fixture files, plans, and command results with the Rust `jsonschema` crate.

Run the focused suite with:

```sh
cargo test -p wt-cli --test acceptance
```

The suite includes the decimal TSX vectors under `examples/template-number-decimal-step/`, including the retained `invalid-tsx.tsx` demanded-parse case. A demanded helper parse failure must be reported as incomplete analysis; a guarded helper call must not parse the file.

The optional shared-query workload is ignored by default. It creates 10,000 files containing 104,860,000 bytes (slightly over 100 MiB) and runs 25, 100, and 1,000 simple rules. It reports measured work counts and asserts no timing threshold:

```sh
cargo test -p wt-cli --release --locked --test acceptance performance_matrix_work_counts_10k_files_100mib_and_25_100_1000_rules -- --ignored --nocapture
```

## Executed shared-query workload

Executed on Linux x86-64, kernel 7.0.0-31-generic, Intel Core i7-6600U (four logical CPUs), Rust 1.94.0, release profile. Backend versions are pinned in `Cargo.lock` (Rhai 1.26.1, regex 1.12.2, tree-sitter 0.24.7). Persistent caches were bypassed, optimizer was `auto`, and the default admitted three workers.

| Rules | Source reads | Bytes hashed | Logical query requests | Physical text evaluations | Shared-result hits |
|---:|---:|---:|---:|---:|---:|
| 25 | 10,000 | 104,860,000 | 250,000 | 10,000 | 240,000 |
| 100 | 10,000 | 104,860,000 | 1,000,000 | 10,000 | 990,000 |
| 1,000 | 10,000 | 104,860,000 | 10,000,000 | 10,000 | 9,990,000 |

All three scans completed without findings or analysis errors. The combined test took 954.18 seconds, including corpus/package creation and all three scans; this is not an isolated per-scan timing. CPU time and peak RSS were not measured. The corpus and rule definitions are generated by the test itself. A subsequent accounting correction changed logical step/native-byte counters; the table records source/query work rather than those corrected counters.

This covers the identical-text-query scenario. The full specification's distinct-pattern, JSX-scale, warm-cache, and mutation performance matrix remains unmeasured. Smaller automated tests cover regex sharing, parser sharing, cache invalidation, and reference/parallel result equivalence.
